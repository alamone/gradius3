# START 画面で背景の色が化ける件（Issue #20）

## 結論

**面の途中のエリアから始めたときだけ、`$00F30A` のパレット一括ロードが走らない。**

純正スタート・エリアA（位置0）スタート・死んでからの再開では走る。だから直前の
パレットの状態が START 画面に残る。「死んでからの再開では起きない」のは、再開が
特別なのではなく、**再開ではこのロードが走るから**。

## 根拠（実測）

MAME 0.288、パレットRAM `$080000-$080FFF` への書き込みを、書いた側の PC ごとに
数えた。START 画面（`$40029 == 02`）に入ってから 400 フレーム分。

| 開始のしかた | パレット書き込み | 書いた PC の数 | `$00F30A` |
|---|---|---|---|
| 純正スタート（START のみ） | 5798 | 13 | **×2240** |
| メニュー → 1面 エリアA（位置0） | 5803 | 13 | **×2240** |
| 死んでからの再開 | 5256 | 11 | **×2240** |
| メニュー → 3面 エリア7（面の途中） | 3704 | 11 | **なし** |

3つの経路で走り、走らないのは1つだけ。そしてその1つが不具合の出る経路。

`$00F30A` は純正のコードで、純正スタートでも走っている（改造とは関係ない）。

## そちらのビルドにも当てはまるか

当てはまる。0.4.16 の BPS パッチを純正ROMに当てて、純正との差分を取ったところ、
`$00F30A` 付近は**改変されていない**。

（計測そのものは私の改造ROMで取ったもの。私のビルドではメニューのパレット復元の
誤差が成分あたり1ビットしかないので、残っても目では見えない。そちらで色が化けて
見えるなら、復元の誤差が大きいか、復元のタイミングが START 画面より後か、の
どちらかだと思う。）

## 直し方の案（3つ、上から順におすすめ）

1. **面の途中から始めるときに `$00F30A` のロードを走らせる。**
   ゲーム自身の仕組みをそのまま使うので、副作用が読みやすい。
2. **メニューのパレット復元を可逆にする。** 残るものが無ければ、ロードが走らなくても
   困らない。
3. **面の途中から始めるときはパレットを暗くしない。** 一番安全だが、見た目は変わる。

## 確かめ方（この Lua を MAME に渡すだけ）

ROM の中身は要りません。自分の環境で同じ数字が出せます。

```lua
-- palcount.lua
-- mame gradius3j -autoboot_script palcount.lua -autoboot_delay 1 \
--   -video none -sound none -nothrottle -seconds_to_run 900
local frame, armed, mark, total = 0, false, 0, 0
local by_pc, mem, cpu = {}, nil, nil
local function tick()
  frame = frame + 1
  if frame == 240 then
    cpu = manager.machine.devices[":maincpu"]
    mem = cpu.spaces["program"]
    -- 書き込みタップは終わりの番地を奇数にすること
    G3_TAP = mem:install_write_tap(0x80000, 0x80FFF, "pal", function()
      if not armed then return end
      total = total + 1
      local pc = cpu.state["PC"].value
      by_pc[pc] = (by_pc[pc] or 0) + 1
    end)
  end
  if not mem then return end
  -- $40029 == 02 は START 表示。そこから 400 フレーム数える
  if not armed and mem:read_u8(0x40029) == 0x02 then
    armed, mark = true, frame + 400
  end
  if armed and frame >= mark then
    local rows = {}
    for pc, n in pairs(by_pc) do rows[#rows + 1] = { pc, n } end
    table.sort(rows, function(a, b) return a[2] > b[2] end)
    print(string.format("palette writes %d  (PC %d種)", total, #rows))
    for i = 1, math.min(#rows, 8) do
      print(string.format("   PC $%06X  x%d", rows[i][1], rows[i][2]))
    end
    manager.machine:exit()
  end
end
G3_SUB = emu.add_machine_frame_notifier(tick)
```

メニューで「面の途中のエリア」を選んで始めると `$00F30A` が出ない。
エリアA（位置0）や、死んでからの再開では出る。これが違いです。

## 関係しそうな他の Issue

#19（5面 ❷ で中ボスが出る・ボスの曲にならない）と #29（3面 ❶ で逆さ火山の敵が続く）
は、これとは**別の仕組み**だと思う。面のスクリプトは「位置で引く出来事の並び」で、
カーソルが `$400C0` にある。位置だけ飛ばすとカーソルが進まないので、出来事が
出なかったり、まとめて出たりする。パレットの件（`$00F30A`）とは別件。
必要なら #19・#29 も調べます。

## 追記：そちらの 0.4.16 を実際に動かして分かったこと

0.4.16 の BPS を純正に当てて MAME で動かしました（ROMの中身は渡しません。当て方は
配布ページのツールと同じです）。

### 1. `$00F30A` は改変されていない

純正との差分を取りました。0.4.16 がメインROMで書き換えているのは 2239 バイト・95か所
ですが、`$00F30A` の周辺は**一切触っていません**。なので上の結論はそのまま当てはまります。

### 2. `$00DAAC` がパレットに 4000 回書いています

そちらのビルドで START 表示の前後を数えたところ、`$00DAAC` から **4000回** の
パレット書き込みがありました（純正には無い書き込みです。`$00D8F6..$00DB08` は
0.4.16 が使っている領域なので、そちらの改造コードだと思います）。

**色が化ける原因を探すなら、まずここだと思います。** 暗くする／戻す処理がここなら、
戻し方が完全でないか、戻すのが START 表示より後か、のどちらかです。
`$00F30A` が走らない面の途中スタートでは、ここが残したものがそのまま画面に出ます。

### 3. 参考：MAME で自動テストするときのコツ

そちらの Claude が自動化するときに使えると思います。

- **コインはタイトルが出てから**（`$40007 == 02`）。デモ中に入れても消えます。
  これで3回ハマりました。
- **メニューを開く START は短く**（5フレーム程度）。長いと、開いた直後の同じ押下を
  メニューが「開始」と読んで、そのままゲームが始まります。
- **メニューが出ている間 `$40029` は 00 のまま**です。モードの変化を待つ作りにすると、
  メニューを撮り逃してタイプ選択の画面しか映りません。
- メニューの上下左右は **14フレームくらい押す**と効きます。6フレームでは効きませんでした。
- スナップショットは `-video none` のままでも撮れます（画面を出す必要はありません）。
